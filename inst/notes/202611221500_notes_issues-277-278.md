## Follow-up: input not pre-filling (same session)
User reported the date box no longer pre-filled. Cause: the first JS used `n < 10`, and `tags$script()` HTML-escapes the `<`, giving a browser SyntaxError so the script never ran. Fixed by using `String(n).padStart(2, "0")` (no `<`). Verified with headless Chrome (en-US, via CDP): `#clientTime` = `2026-11-22`, no JS exceptions. This supersedes the earlier "in-browser check not done" note. Lesson: avoid `<`/`&` in inline `tags$script()` strings (or wrap in `HTML()`).

## Follow-up: Posit Connect Cloud republish failed (log fugazetteer-18.log)
Error: "Unable to connect to worker after 60.00 seconds; startup took too long." Cause: `app.R` ran `remotes::install_github("alexmitrani/Repeatr", build_vignettes = TRUE, dependencies = TRUE)` on every start; on the server (where Repeatr is already installed at build time, from GitHub commit 17f1a23) this also upgraded/compiled 69 packages from source (terra, sf, stringi...), exceeding the 60 s limit. Fix: install only when `interactive()` (RStudio - keeps the GitHub remote metadata used at publish time) or when Repeatr is missing, and with `upgrade = "never"`.
Correction: commit 17f1a23 (what Connect Cloud built) DOES contain the `padStart` fix; the earlier claim that it predated it was wrong, and everything was already pushed. In the committed app.R the install_github line was commented out, but the working copy that Posit Publisher uploaded had it active (the log shows "Downloading GitHub repo alexmitrani/Repeatr@HEAD" at runtime, after "Shiny application starting"). The `gitcreds` warning is harmless. Unverified: why earlier deploys with the same line succeeded (probably fewer packages needed upgrading before Connect Cloud's package snapshot and CRAN diverged).
