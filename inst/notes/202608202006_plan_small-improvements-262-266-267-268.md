## #268 — "with NA" (root cause found, not a guess)

`R/recap.R`'s `recap()` builds `bands <- played_with %>% filter(gid==mygid) %>% pull(played_with)`
and only appends " with ..." when `length(bands) > 0`. That logic is correct
for the package's real `played_with` table (`R/Repeatr_1.R` line ~1160:
`filter(is.na(played_with)==FALSE)` — one row per gid/band pair, no-band
shows simply absent).

The bug is at the call site: `inst/shiny/Fugazetteer/app.R` line 3347 passes
`myplayed_with = played_with` — but by that point in the script, the
top-level name `played_with` has been **shadowed** (lines 97–108) into a
different shape: one row per **gid** (left-joined from `othervariables`),
with `played_with = NA` for shows with no other bands. That shape is used
correctly elsewhere in app.R (map popups, band-summary tab, etc.), but when
passed into `recap()` under the same parameter name, `bands` becomes a
one-element vector `NA` instead of an empty vector — `length(bands)==1`, so
`paste0(" with ", oxford_join(NA))` produces literally `" with NA"`. Confirmed
against the raw CSV: `rome-italy-60792` (the show named in the issue) has a
genuinely empty `played_with` field.

**Fix**: at `inst/shiny/Fugazetteer/app.R:3347`, change
`myplayed_with = played_with,` to `myplayed_with = Repeatr::played_with,` —
this bypasses the app-local reshaped variable and uses the same long-format
table `recap()` would use by default if the argument were omitted entirely.
Minimal, targeted, no changes to the ~15 other consumers of app.R's reshaped
`played_with` variable (out of scope and not needed).

## #262 — northernmost/southernmost note

Add a new `note_*` function in `R/recap.R`, next to `note_record_attendance`/
`note_record_price`/`note_festival` (same file, ~line 526-577), following
their established pattern (independent of `has_recording`, NA-guarded like
`note_record_price` rather than unguarded like `note_record_attendance`,
since `latitude` can in principle be missing):

```r
note_record_latitude <- function(latitude, shows_data) {
  if (is.na(latitude)) return(NA_character_)
  if (latitude==max(shows_data$latitude, na.rm = TRUE)) {
    "This was the northernmost Fugazi show."
  } else if (latitude==min(shows_data$latitude, na.rm = TRUE)) {
    "This was the southernmost Fugazi show."
  } else {
    NA_character_
  }
}
```

Wire it in next to the other three record notes: compute
`latitude_record_note <- note_record_latitude(this_show$latitude, shows_data)`
alongside `attendance_record_note`/`price_record_note`/`festival_note`
(~recap.R:882-884), and add it to the `c(...)` at ~recap.R:1103.

## #267 — furthest-from-home note

`recap()` already computes `trip_links <- classify_show_trips(shows_data, home_lat, home_lon)`
(~recap.R:655), which has `distance_home_km` for **every** show, not just
this one — reuse it directly rather than recomputing anything.

```r
note_record_distance_home <- function(distance_home_km, trip_links) {
  if (is.na(distance_home_km)) return(NA_character_)
  if (distance_home_km==max(trip_links$distance_home_km, na.rm = TRUE)) {
    "This was the show furthest from home Fugazi ever played."
  } else {
    NA_character_
  }
}
```

Only the "furthest" direction is in scope (that's what #267 asks for — not
"closest to home", which would need its own design decision about whether
near-home DC shows should all tie for it and isn't part of this issue).

Wire in the same way: `distance_record_note <- note_record_distance_home(distance_home_km, trip_links)`
near the other record notes, added to the same `c(...)` list.

## #266 — "Vhs audio" → "VHS audio"

Confirmed: `R/Repeatr_1.R` (~line 131-136) already normalizes every raw
variant (`"VHS"`, `"VHS Tape"`, `"VHS audio"`) to `"VHS audio"` at the data
layer — so the stored `othervariables$original_source` value, and
fugazibase's exported copy (which selects `original_source` straight from
`othervariables`, unmodified — `R/export_fugazibase_data.R:84`), are already
correct. The bug is purely a `recap.R` display-time regression: `fix_caps()`
(`R/recap.R:48-64`) sentence-cases any all-caps word not in its `acronyms`
whitelist, and `"VHS"` isn't in it — turning the correct `"VHS audio"` back
into `"Vhs audio"` only when rendered in the recap tab's paragraph2. Exact
same bug class as the prior DAT/CD/PRS fix
(`inst/notes/202608171000_notes_fix-caps-acronym-exceptions.md`).

**Fix**: `R/recap.R:52`, change
`acronyms <- c("DAT", "CD", "PRS")` to `acronyms <- c("DAT", "CD", "PRS", "VHS")`.

No data-layer or fugazibase changes needed — confirmed both are already
correct.
