# Add "recap" tab to Fugazetteer Shiny app

## Context

The Fugazetteer Shiny app (`inst/shiny/Fugazetteer/app.R`) has a "flow" section with many sub-tabs (shows, with, attendance, xray, renditions, matrix, transition, sets, stacks), each surfacing one slice of the Fugazi Live Series dataset. There is currently no single place to see everything about *one specific show* — a user wanting "what should I know before listening to this show" has to piece it together from several tabs. The "recap" tab closes that gap: pick one show and see its story (date/venue/tour context, map, and — if a recording exists — a detailed tracklist) in one place, with a downloadable take-away document.

Design decisions already confirmed with the user:
- **Download format**: self-contained HTML via `rmarkdown::render()`, not PDF (no LaTeX/tinytex or webshot2/chromote infra exists anywhere in this project, and none should be added; `rmarkdown`+`knitr` are already Depends, pandoc is already used for vignette builds).
- **Filter scope**: the existing years/tours filter row above the flow sub-tabs only narrows which show appears in the recap show-selector dropdown (same as "stacks"). Once a show is picked, all historical/context stats use the full all-time dataset.
- **Rendition stats basis**: "rendition number" and "total renditions" are based on **recorded** renditions (`duration_data_da`), the same source as `duration_summary`/`position_summary`, so every per-song stat on the page is internally consistent.
- **Tracklist scope**: songs only (`tracktype==1`), matching what `duration_data_da` already contains — no interludes.

## New derivation logic — `R/recap.R` (new file, exported `recap()` function)

Every missing metric (rendition number, tour position, prev/next show on tour, prior-visit counts by country/state/city/venue, per-release song-count breakdown) is a **pure derivation from data already exported to both Repeatr and fugazibase** (`shows_data`, `Repeatr1`, `duration_data_da`, `releasesdatalookup`, `duration_summary`, `position_summary`, `played_with`). No new source data is introduced, so this does **not** need new precomputed `.rda` datasets, a `data-raw` rebuild, or a `fugazibase` export change — it only needs a new general-purpose function, following the existing pattern of `R/stacks.R`'s `stacks()` (override-or-lazy-load params, one exported function per file, roxygen doc block with `@examples` using a real gid like `"washington-dc-usa-13196"`).

```r
#' @export
recap <- function(mygid,
                   myshows_data = NULL, myduration_data_da = NULL,
                   myrepeatr1 = NULL, myreleasesdatalookup = NULL,
                   myduration_summary = NULL, myposition_summary = NULL,
                   myplayed_with = NULL) { ... }
```
Falls back to the lazy-loaded package defaults (`Repeatr::shows_data` etc.) when a `my*` arg is `NULL`, exactly like `stacks()` (`R/stacks.R:24-33`). **Important**: the Shiny server must pass the app's locally-rebuilt objects (`shows_data`, `duration_data_da`, `played_with`, `Repeatr1`, `releasesdatalookup`, `duration_summary`, `position_summary` as pre-processed at `app.R:22-273`), not rely on the fallback, so recap numbers match the rest of the app (e.g. city disambiguation). The Rmd template (rendered outside the Shiny session) *should* use the fallback/defaults — see below.

Return value: a list with:
- `context` — named list of scalar fields for the prose: `date, venue, city, subdivision, country, where_played, played_with_text, tour, tour_position, tour_total, previous_show_text, next_show_text, country_visit_number, subdivision_visit_number, city_visit_number, venue_visit_number, has_recording, n_songs, minutes, sound_quality, release_breakdown_text, url, fls_link`.
- `tracklist` — `NULL` if no recording, else one row per song: `track_number, title, minutes, minutes_max, release_title, release_date, rendition_number, renditions, position, position_mean`.
- `release_breakdown` — `NULL` if no recording, else `release_title, release_date, n_songs` (also folded into `context$release_breakdown_text`).

Key derivation logic (internal, unexported helpers in the same file):
- **Rendition number**: `myduration_data_da %>% arrange(date, song_number) %>% group_by(title) %>% mutate(rendition_number = row_number())`.
- **Tour position + prev/next show**: `myshows_data %>% arrange(tour, date) %>% group_by(tour) %>% mutate(tour_position = row_number(), tour_total = n(), previous_venue = lag(venue), previous_date = lag(date), next_venue = lead(venue), next_date = lead(date))`.
- **Prior-visit counts** (strictly before this show's date, `+1` for "this is the Nth time"): country by `country`; city by `city, country`; venue by `venue, city, country`; subdivision by `subdivision, country`, returning `NA` when `subdivision` is `NA` (so the prose can omit that clause).
- **Release breakdown**: `myrepeatr1 %>% filter(gid==mygid, tracktype==1) %>% distinct(title, rid, release_title) %>% count(release_title, rid, name="n_songs") %>% mutate(release_title = ifelse(is.na(release_title), "unreleased", release_title)) %>% left_join(myreleasesdatalookup %>% select(rid, release_date), by="rid")` — matches the existing `"unreleased"` convention used repeatedly in `R/Repeatr_1.R` (e.g. lines 1124, 1489, 1659).
- **Tracklist assembly**: `duration_data_da` (confirmed at `R/Repeatr_1.R:1594-1633`) does **not** carry `rid`/`release_title`/`track_number` — join back to `Repeatr1 %>% filter(tracktype==1)` on `gid` + `song_number` to recover them, then join `releasesdatalookup` on `rid` for `release_date`, then join `duration_summary`/`position_summary` on `title` for `minutes_max`/`renditions`/`position_mean`, then bring in `rendition_number`.
- **Prose text** (context paragraph 1, "today"-tab style minus "years ago" framing): reuse the ordinal-suffix logic (`app.R:1300-1308`/`1387-1414`) and the `where_played`/`played_with_text` construction pattern from `today_data`/`played_with_flat`/`format_played_with()`/`add_subdivision_to_city()` (`app.R:243-273`) — but since those helpers live in `app.R`, not the package, replicate the small (~15 line) band-joining/subdivision logic inline in `R/recap.R` rather than having the package depend on app.R internals.

Run `devtools::document()` after writing `R/recap.R` to generate `man/recap.Rd` and update `NAMESPACE` (no manual edits to those).

## New file — `inst/shiny/Fugazetteer/recap_template.Rmd`

Colocated with `app.R` (Shiny sets the working directory to the app's own folder at runtime; no `inst/rmd/`-style convention exists elsewhere in this repo to follow instead).

```yaml
---
title: "Fugazi Live Series — Recap"
output:
  html_document:
    self_contained: true
params:
  gid: NA
---
```
The template calls `library(Repeatr)` and `Repeatr::recap(mygid = params$gid)` **using recap()'s default/lazy-loaded data**, not trying to pass the live Shiny session's objects across the `rmarkdown::render()` boundary — a deliberate, minor, documented divergence (only affects cosmetic details like city disambiguation, not any substantive recap numbers). Content: inline-R heading + FLS link, the two prose paragraphs, a `leaflet(...)` map chunk, and (conditionally on `has_recording`) `knitr::kable(result$tracklist)` — use `kable`, not a live `DT::datatable`, since a static table is simpler and always renders correctly in a self-contained offline document.

Leaflet **does** support self-contained embedding via pandoc's base64-inlining of htmlwidget dependencies — no new package needed. Two things to verify in testing: (1) `rmarkdown::render()` needs a working pandoc (already required for this package's vignettes); (2) the embedded map's tile images (`addProviderTiles`) still load live from the internet when the recipient *opens* the HTML file — same as every other map in this app, not a new limitation, but worth a one-line caveat in the vignette.

**`downloadHandler` content function** — render a copy in `tempdir()`, not the installed template path directly, to avoid permission issues (this app is deployed to shinyapps.io per `sourcestext` at `app.R:18`) and concurrent-session collisions:
```r
content = function(file) {
  tmp_rmd <- file.path(tempdir(), "recap_template.Rmd")
  file.copy("recap_template.Rmd", tmp_rmd, overwrite = TRUE)
  rmarkdown::render(input = tmp_rmd, output_file = file,
                     params = list(gid = input$search_shows_recap),
                     envir = new.env(parent = globalenv()))
}
```

```markdown
## recap

Here you can choose any single show (out of the shows with set lists available to date) and see everything about it in one place: the venue and date with a link to the corresponding page of the [Fugazi Live Series](https://www.dischord.com/fugazi_live_series) site, where it fits in its tour, how many times Fugazi had previously played in that country, state/province, city and venue, and (if a recording of the show exists) how many songs were played, how long the recording runs, its sound quality rating, and which releases its songs are drawn from.

A map shows the location of the show.

If a recording exists, a detailed tracklist is also shown, giving each song's duration, its maximum recorded duration across all Fugazi shows, the release (and release date) it is drawn from, which numbered rendition of the song this was, its total number of recorded renditions, its position in the set, and its average position across all recorded renditions.

The whole page can be downloaded as a self-contained HTML take-away document using the download button at the top of the page to the right of the 'show' selection box.
```
